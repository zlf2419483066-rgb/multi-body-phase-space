# Contributing

Issues and pull requests are welcome. Please describe the scientific or software question being addressed, the affected demo, the validation scope, and any change in public behavior.

Before opening a pull request:

1. run the relevant unit suite from the repository root;
2. add or update a regression test for behavior changes;
3. update the affected README or validation note when the supported scope changes;
4. keep generated catalogs, local paths, credentials, and private research notes out of commits.

Changes to physical definitions, canonicalization rules, or the boundary between candidate and effective topologies should include a short rationale and an explicit statement of what remains unvalidated.
